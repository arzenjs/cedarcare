# CedarCare Family Clinic (portfolio demo)

A complete clinic website with online appointment booking, secure staff login, a staff dashboard and transactional email. **CedarCare is fictional.** All doctors, qualifications and contact details are placeholders, and no real patient data should ever be entered.

## Features
- Public site: home, about, doctors (+ filter and detail pages), services, contact, privacy, terms, 404 / error / loading states.
- Booking without an account: doctor, service, date, time, contact details, consent. Only genuinely free times are shown.
- Server-validated scheduling: working days, sessions and breaks, per-doctor visit length, holidays, doctor leave, booking window (30 days) and minimum notice (2 hours).
- Double-booking protection (see below), non-guessable confirmation link, unique public reference.
- Confirmation email through Resend. A failed email never undoes a saved booking; status is recorded and admins can retry.
- Staff login (Auth.js), roles `admin` and `staff`, invitation-only account creation with hashed, expiring, single-use tokens.
- Staff dashboard: live counts, search (reference / name / phone), filters (date / doctor / status), pagination, status actions with confirmation, mobile cards.
- Admin: invite and deactivate staff, revoke invitations, retry failed emails.

## Technology
Next.js 16 (App Router, JavaScript), React 19, Tailwind CSS 4, Lucide React, Motion (`motion/react`, the successor to Framer Motion), MongoDB + Mongoose, Auth.js v5 (`next-auth@5.0.0-beta.32`; v5 is only published under the `beta` tag, v4 is the stable line but does not target the App Router), bcryptjs, Resend, ESLint.
After installing, run `npm ls next react tailwindcss mongoose next-auth motion` to see the exact versions in your lockfile.

## Prerequisites
Node.js 20.9 or newer (22 recommended), npm, and a MongoDB database (local or Atlas free tier).

## Install
```bash
npm install next@latest react@latest react-dom@latest mongoose lucide-react motion resend bcryptjs next-auth@5.0.0-beta.32
npm install -D tailwindcss @tailwindcss/postcss eslint eslint-config-next
```
This writes `package-lock.json`; commit it. If the installed `next-auth` beta is newer than `.32`, keep that one (it contains security fixes).

## Environment
```bash
cp .env.example .env.local
```
Fill in `MONGODB_URI`, `AUTH_SECRET` (generate with `npx auth secret`), `AUTH_URL` / `NEXT_PUBLIC_SITE_URL`, and the Resend values. `.env.local` is git-ignored.

## MongoDB
- **Atlas:** create a free cluster, add a database user, allow your IP, and paste the connection string into `MONGODB_URI` (include a database name such as `/cedarcare`).
- **Local:** `mongodb://127.0.0.1:27017/cedarcare`.
- **No replica set is required.** Indexes are created automatically on first use.

### How double booking is prevented
Slots are fixed-length and generated by one function (`src/lib/scheduling.js`), so two appointments overlap only if they start at the same moment. Each active appointment stores `slotKey = doctorId|startTime` with a **unique, sparse index**. When two patients submit at once, MongoDB accepts one insert and rejects the other (duplicate-key error), which the API turns into "that time is no longer available" (HTTP 409). Cancelling or marking a no-show removes `slotKey`, freeing the slot. A unique index on start time alone would be wrong (it would block different doctors), which is why the doctor is part of the key. Transactions are therefore not needed.

## Create the first administrator
Set `ADMIN_EMAIL` and `ADMIN_PASSWORD` (12+ characters) in `.env.local`, then:
```bash
npm run create-admin
```
It hashes the password, does nothing if an admin already exists, and is not exposed through the website. Afterwards remove `ADMIN_PASSWORD` from `.env.local`. Sign in at `/staff/login`, open **Staff accounts** and invite colleagues.

## Resend
1. Create an account at resend.com and an API key (`RESEND_API_KEY`).
2. For testing without a domain, use `RESEND_FROM_EMAIL=CedarCare <onboarding@resend.dev>`. Resend only delivers such test mail to your own account email.
3. For real delivery, add your domain in Resend and create the DNS records it lists (SPF/DKIM) at your DNS provider; you need access to the domain's DNS settings. Then use an address on that domain.
4. The `*.example` addresses in the clinic config are placeholders and cannot send or receive mail.
Without a key the site still works: bookings are saved and marked `skipped`, and invitations report that email was not sent.

## Deployment (Vercel example)
1. Push to GitHub and import the repo in Vercel.
2. Add every variable from `.env.example` (set `AUTH_URL` and `NEXT_PUBLIC_SITE_URL` to the live URL).
3. In Atlas, allow Vercel's access (Network Access; `0.0.0.0/0` with a strong DB password is the simple option).
4. Deploy, then run `npm run create-admin` once from your machine with `MONGODB_URI` pointing at the production database.
Any Node host (VPS, Railway, Render) also works with `npm run build && npm start`.

## Security notes
- Authorization is enforced on the server in every staff/admin page (`requireUser`) and API (`requireApiUser`) in `src/lib/access.js`. The role is read from the database on each request, so deactivation takes effect immediately. The footer "Staff Portal" link is only a link.
- There is no `proxy.js`/middleware on purpose: checks live next to the data they protect.
- Passwords are bcrypt-hashed; invitation and confirmation tokens are stored only as SHA-256 hashes; sessions are signed JWT cookies (8 hours, secure in production).
- Login ignores any redirect URL from the browser; the destination comes from the stored role.

## Known limitations
- **Rate limiting is in-memory** (`src/lib/security.js`). It is fine on one server but not shared between serverless instances. For production, back `rateLimit()` with Upstash Redis or similar.
- Auth.js v5 is still a beta release line.
- Doctors and schedules live in `src/data/doctors.js`, not in the database; changing them means editing the file and redeploying. Holidays and leave are also in config files. There is no admin screen for scheduling.
- The Indian time zone has no daylight saving, so fixed `+05:30` conversion is used. Adding a zone with daylight saving would require a date library.
- Doctor portraits are monogram placeholders; replace `Avatar` with `next/image` and real photos.
- Patients cannot cancel online (staff do it). Appointments do not send reminder emails.
- This is a demo, not a certified health-records system. Do not store real patient data.

## Replace the fictional details
- Clinic name, address, phone, email, WhatsApp number, hours, holidays, booking rules: `src/config/clinic.js`.
- Doctors, qualifications and weekly schedules: `src/data/doctors.js`.
- Services: `src/data/services.js`. FAQs: `src/data/faqs.js`. Navigation: `src/config/navigation.js`.
- Colours and fonts: `src/app/globals.css` and `src/app/layout.js`.
- Optional interactive map: set `NEXT_PUBLIC_GOOGLE_MAPS_EMBED_KEY`; without it the site uses plain Google Maps links.
